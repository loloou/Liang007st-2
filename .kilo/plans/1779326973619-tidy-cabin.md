# 项目逻辑检查与 Bug 修复计划

## 目标
修复当前已知的生图历史、生成结果右键菜单、历史预览保存、历史键盘切图，以及自定义并行生图交互/布局问题。项目主要涉及 `client/src/App.tsx`、`client/src/components/ResultPanel.tsx`、`client/src/components/HistoryFullPreview.tsx`、`client/src/components/ControlPanel.tsx`、`client/src/utils/download.ts`。

## 已定位现状
- `ResultPanel.tsx:84-92` 使用 `clientX/clientY` 记录右键坐标，菜单在 `ResultPanel.tsx:524-535` 用 `position: fixed` 渲染；在历史面板点击历史后，结果区容器/布局可能导致坐标与视觉位置不一致或边界计算不完整。
- `HistoryFullPreview.tsx:82-88` 保存使用 `extendedImage.originalUrl || image.url`，但历史图片在生成时会把缩略图放在 `url`、原图放在 `originalUrl`；保存失败可能来自跨域 fetch、过期 URL、或点击事件被外层遮罩/拖拽逻辑干扰。
- 历史双击预览目前只传入单张图片：`App.tsx:2160`、`App.tsx:2318`，`HistoryFullPreview` 不知道当前历史条目的图片数组，因此无法左右切换。
- 自定义并行生图在 `ControlPanel.tsx:470-500` 当前是按钮 + number input；`ResultPanel.tsx:227-323` 固定网格展示所有槽位，缺少“全部槽位/单槽位聚焦/右侧小图标切换”等视图模式。
- 当前 `handleGenerate` 会把每个并行槽位加入 `generationSlots`，并在第一批结果到达时才 `setResults(prev => (prev.length > 0 ? prev : validImages))`，这与“并行槽位可占满结果区，也可只在主结果右侧增加小图标切换槽位视图”的需求相近，但还未形成明确 UI 模式。

## 实施步骤

### 1. 修复生成结果右键菜单位置
1. 在 `ResultPanel.tsx` 中保留 `clientX/clientY`，但改进菜单定位为：
   - 打开菜单时使用鼠标坐标；
   - 渲染后通过 `ctxRef.current.getBoundingClientRect()` 或预估尺寸进行二次 clamp；
   - 确保 `left/top` 使用视口坐标并限制在 `8px ~ window.innerWidth/Height - menuSize - 8px`。
2. 对并行槽位图片和普通结果主图统一使用同一个 `handleContextMenu`。
3. 保存/复制/发送 Eagle 时优先使用原图 URL：`(img as { originalUrl?: string }).originalUrl || img.url`，避免历史恢复后右键保存到缩略图。

### 2. 修复历史全屏预览保存
1. 在 `download.ts` 增强 `downloadImage`：
   - 支持 `data:` URL 直接生成 Blob 下载，避免对 data URL fetch 不稳定；
   - 对普通 URL fetch 失败时，增加 `<a href=url download>` 的兜底触发，尤其适合 Electron/浏览器可直接下载但 fetch 跨域失败的图片；
   - 保持原有 blob URL 逻辑。
2. 在 `HistoryFullPreview.tsx` 中：
   - 保存 URL 优先 `originalUrl`，其次当前显示 `imageUrl`，最后 `image.url`；
   - 保存按钮 `onClick` 继续 `stopPropagation`，并对下载失败给出可见错误状态/console 信息，避免静默失败；
   - 若 `imageUrl` 初始化逻辑存在 render 阶段 setState 的风险，迁移到 `useEffect([image])`，减少预览切换和保存状态异常。

### 3. 生图历史预览支持左右方向键切换
1. 在 `App.tsx` 增加历史预览状态，从单个 `GeneratedImage | null` 扩展为：
   - `historyPreviewImages: GeneratedImage[]`
   - `historyPreviewIndex: number`
   - 或一个对象 `{ images, index } | null`。
2. 历史列表/网格双击时传入当前历史条目的完整 `entry.results` 和当前图片索引（默认 0）。
3. 修改 `HistoryFullPreview` props：
   - `images?: GeneratedImage[]`
   - `index?: number`
   - `onIndexChange?: (next: number) => void`
4. 在 `HistoryFullPreview` 中监听键盘：
   - `Escape` 关闭；
   - `ArrowLeft` 切换上一张；
   - `ArrowRight` 切换下一张；
   - 切换时重置 `zoom`、`offset`、拖拽 ref 和下载状态。
5. 在顶部控制栏或左右侧增加上一张/下一张按钮和 `当前/总数` 标识；只有多图历史才显示。

### 4. 优化自定义并行生图设置为下拉
1. 在 `ControlPanel.tsx:470-500` 将按钮 + number input 改为单个下拉选择：
   - 选项：`1 路（默认）`、`2 路`、`3 路`、`4 路`；
   - 保留说明文字，但简化为“每次点击创建 N 个独立槽位”。
2. 保持 `parallelCount` 上限 4，与 `App.tsx:512` 的 clamp 一致。

### 5. 优化并行槽位结果展示模式
1. 在 `App.tsx` 增加结果视图状态：
   - `slotViewMode: 'grid' | 'focus'`，默认建议 `focus`，减少多槽位占满界面的干扰；
   - `activeSlotId: string | null`。
2. 在生成新槽位后：
   - 若没有 active slot，默认选择最新创建的第一个槽位；
   - 槽位成功后，如果当前聚焦该槽位，将 `results` 同步为该槽位结果。
3. 扩展 `ResultPanel` props：
   - `slotViewMode`、`setSlotViewMode`；
   - `activeSlotId`、`setActiveSlotId`。
4. `ResultPanel` 中支持两种布局：
   - **全部槽位视图（grid）**：沿用当前网格，所有槽位占满生成结果区，便于比较并行结果。
   - **聚焦视图（focus）**：中间保持当前主结果预览；在右侧或底部增加小型槽位切换条（状态点/缩略图/序号），点击切换不同槽位，运行中显示 spinner，错误显示红色状态，可关闭/重试。
5. 交互细节：
   - 标题栏增加“全部槽位 / 聚焦槽位”切换按钮；
   - 小图标切换槽位时调用 `onSelectSlot`，同步 `results`、`resultActiveIdx`、`selectedImageIds`；
   - 关闭 active slot 后自动选择下一个可用槽位；
   - 对没有结果但运行中的槽位，聚焦区显示进度；对失败槽位显示错误与重试。

### 6. 验证
1. 运行 `npm run type-check --workspace client` 或 `npm run build --workspace client`，确认 TypeScript/Vite 构建通过。
2. 手工验证：
   - 打开历史面板，单击历史恢复到结果区后，右键菜单出现在鼠标附近且不越界；
   - 双击历史图片进入全屏预览，点击保存图片可下载；
   - 历史条目有多张图时，左右方向键和按钮可切换；
   - 自定义并行下拉可切换 1-4 路；
   - 并行生成后可在全部槽位视图与聚焦槽位视图间切换，右侧/底部小图标能切换槽位。

## 风险与注意事项
- 历史中保存的是缩略图 + `originalUrl`，历史越久远原图 URL 可能过期；下载增强只能兜底触发浏览器下载，无法保证远端过期 URL 可用。
- `App.tsx` 文件较大，实施时应尽量局部修改，避免顺手重构引入回归。
- `HistoryFullPreview` 当前在 render 阶段基于 `image` 执行 setState，修复时应小心保持 hook 顺序并避免 early return 前后新增条件 hook。
