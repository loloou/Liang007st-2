## P0 重构：App.tsx 状态拆分（第三轮）

新建文件：
- `client/src/store/generationStore.ts` — 生图参数、结果、历史记录（含 handleGenerate 核心逻辑）
- `client/src/store/settingsStore.ts`  — 设置弹窗草稿、模型测试、供应商管理
- `client/src/store/uiStore.ts`        — 所有 UI 状态（弹窗开关、面板尺寸、主题、日志等）
- `client/src/hooks/useAppState.ts`    — 适配层 hook，汇聚三个 store

App.tsx 迁移方式（最小改动）：
1. 删除所有 useState/useEffect/useRef 声明（约 120 行）
2. 在 `function App()` 顶部加 `const s = useAppState();`
3. 全局搜索替换：`prompt` → `s.prompt`，`setPrompt` → `s.setPrompt` 等
4. `logEntries` 相关改为 `s.appendLogEntry` / `s.updateLastLogEntry`
5. handleGenerateRef.current.fn 相关逻辑已内置在 generationStore 的 ratioMismatchDialog.onConfirm 中，可删除

全部零 lint 错误。Zustand v5 已安装，无需额外安装依赖。

### imageClient.ts
1. **buildGeminiEndpoint 空 modelId Bug** - `modelId` 为空时注释变量名 `model` 导致语义混淆，已改名 `resolvedModelId` 并加注释
2. **timer 内存泄漏** - `resp.text()` 抛异常时 `clearTimeout` 未执行，改用 `finally` 保证清理
3. **Gemini 批量调用配置不一致** - 改为 `Promise.allSettled` 并发调用，某张失败不影响其他；部分失败时返回已成功的图片

### App.tsx
4. **参考图 ObjectURL 管理** - cleanup 函数正确负责回收当前批次 URL，`prevRefUrls.current` 在 cleanup 时重置
5. **历史恢复 any 类型** - `img: any` 改为明确的接口类型，消除 TypeScript 类型漏洞
6. **历史恢复覆盖无效 model** - 恢复 model 前检查是否在当前 modelList 中，避免恢复出一个已删除的模型
7. **promptHistory 条数不一致** - 提取 `MAX_PROMPT_HISTORY = 50` 常量，统一写入和清理逻辑
8. **HistoryEntry 类型提取** - `generationHistory` state 由内联对象类型改为独立的 `HistoryEntry` 类型，`safeSaveHistory` 参数从 `any[]` 改为 `HistoryEntry[]`

### settings.ts
9. **makeDefaultConfig activeImageModelId 悬空** - 默认配置 `imageModels: []` 但 `activeImageModelId` 为随机 UUID，永远匹配不到模型。修复为空字符串，让 `getActiveImageModel` 正确走 `imageModels[0] ?? null` fallback

### 建议的 store 划分
- `generationStore.ts` - 生成参数 + 结果 + 状态
- `settingsStore.ts` - API 配置草稿
- `historyStore.ts` - 生成历史
- `uiStore.ts` - 弹窗/面板开关等 UI 状态
